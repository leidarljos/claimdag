#+title: Changelog
#+description: What each claimdag version changed, from CHANGELOG.md.
#+options: toc:nil num:nil

This page is =CHANGELOG.md=. The version line in the workspace
=Cargo.toml= is the version the crates publish.

The [[file:reference.org][reference]] is the current command line. The
[[file:getting-started.org][tutorial]] runs against that command line.

Versions follow semver at 0.x: a minor bump is a feature, a patch is a fix.

* 0.9.1 (2026-11-18)

### Fixes

- Absent-graph errors now point new users to =claimdag upsert --summary "..."= instead of telling them to claim something before any node exists.
- CLI =--help= and invalid =--kind=, =--role=, and =--status= errors now list the valid enum values and option descriptions.
- On an empty directory, =claimdag-tui= now shows a status hint to run =claimdag upsert --summary "..."=, and pressing =R= no longer creates an empty =work.bin=.
- The "also holding work" line is now said once even when =$XDG_RUNTIME_DIR/claimdag= does not exist yet.
- =--dir= now refuses regular files with a clear "not a directory" message on both read and write verbs.
- =claimdag --dir ""= now follows the same empty-value rule as ~CLAIMDAG_DIR=""~: the empty value is ignored and default location lookup is used.
- =claimdag claim --gen 0= is now refused as a generation mismatch, matching =claimdag complete --gen 0= and =--help=.
- =claimdag complete= now prints and logs the node's actual stored terminal status instead of the requested status when called on a node that is already terminal.
- =claimdag help --help= now prints help text instead of failing with an unrecognized subcommand error.
- =claimdag list= and =claimdag get= now show the 8-hex id prefix when a node summary is empty.
- =claimdag upsert --id <ID>= now keeps the existing node's kind when =--kind= is omitted instead of overwriting it with =task=.
- =claimdag-mcp= now reports a clear one-line message when stdin closes before =initialize=.
- =claimdag-mcp= now supports =--help=, =--version=, and =--dir <DIR>=, and exits 2 on unknown or incomplete flags instead of failing on stdin initialize.
- =claimdag-tui= now shows unreadable =work.bin= errors in the status line instead of showing an empty graph with no error.

### Documentation

- The README now writes critical slack as plain text "(delta)" instead of raw LaTeX.
- =--dir= help text now names the full fallback order in both =claimdag= and =claimdag-tui=, matching =claimdag where=.
- =README.md= now uses a user-writable =/tmp/demo-seat= directory instead of =/var/lib/seat=, and =README.md= and =install.org= include =cargo install --locked --path= commands for installing from a checkout.
- =claimdag complete --help= and =claimdag release --help= now render their long descriptions as compact paragraphs instead of one sentence per paragraph.
- =getting-started.org= now shows the ~gen=2~ and =none= outputs from =renew= and =reclaim --lease 60= and clarifies why =complete --gen 2= succeeds in the next step.

* 0.9.0 (2026-11-18)

### Features

- A Model Context Protocol (MCP) client can add a node, link or unlink a dependency, and read one node.
  =claimdag_upsert= keeps the node's status when status is omitted.
  =claimdag_get= returns that row or the status prune kept.
- Every seat of a user finds the same default graph.
  =claimdag where= lists the candidate directories, and =claimdag where --move= migrates the graph.

### Fixes

- A claimdag writer waits at most 1 s for the graph lock.
  It then names the process that has the lock and how to free it.
- A graph refusal from the Model Context Protocol (MCP) server is a tool result with the refusal text.
  A seat can read it.
  An id that is not 32 hex characters is still invalid params.
- A malformed id is reported as a bad id, and the message gives its length.
  A hex prefix of exactly one node names that id and is not used as the id.
- A refused claim now names the holder, the unfinished dependencies, or the generation, and the command that clears it.
  A refused upsert, link, unlink or archive names the node and how to resolve it.
- A refused claimdag command now names the node, its claimant and the command that resolves it.
- A release or complete that names nobody still runs, and so does a release, complete, renew or set_running whose actor is not the holder.
  Each writes =allow=, =warn= and the rule, separated by tabs, on stderr and in =warn.log=.
  A default directory another user owns is opened the same way, with the rule =not-owner=.
  =--force= still appends to =forced.log=.
- A server tool that records a warning puts that line in the tool result, as a text block after the row.
  Stderr and =warn.log= still get the same line.
- A write that resolved the old directory before =claimdag where --move= follows the moved graph.
- CI runs fmt, clippy and the suite on Linux x86-64, Linux arm64 and macOS.
  A seat on macOS now takes the machine name, not localhost.
- Completing a node that prune dropped now returns that node with the status it finished with.
  The answer comes over the Model Context Protocol (MCP).
- Completing or releasing a node that prune dropped after it finished now exits 0 and changes nothing.
- Omitting =--status= on =upsert= keeps the status an existing node already has.
  A holder can rewrite its summary and keep the claim.
  A new node still starts at =todo=.
  An explicit status on held work is still refused.
- When the directory was not named, a running Model Context Protocol (MCP) server resolves it on each call.
  =claimdag where --move= is then the graph the next call reads, and a claim writes there.
  A directory named with =CLAIMDAG_DIR= stays the one the server was given.
- =claim-next= takes the same node for the same graph and the same worker in every process.
  It picked from the graph's hash order, which changes from one process to the next, so one worker on one graph got a different node on each call.
- =claimdag ready= prints =waiting_below= on each JSON row and ~below=N~ on each text row.
  =list= output is unchanged.
- =claimdag-mcp= and =claimdag-tui= now declare Rust 1.88, the floor their dependencies build on.
  Installing either on an older compiler reports that requirement from the crate itself.
  CI checks each crate on the =rust-version= it declares.
- =claimdag_ready_balanced= and =claimdag_claim_next= refuse a role the graph does not store.
  The tool schema lists the seven roles.
  A short assignee is refused as a bad id.

### Documentation

- Each sentence added for a warning label is on its own line.
- The command section of the reference is the help text of claimdag itself.
  The README and getting-started commands run in CI.
- The how-to gives each sentence about the server's tools its own line.

### Miscellaneous

- A =work.bin= that 0.8.0 wrote opens, and saving it again writes the same bytes.
- An integration test now calls every claimdag-mcp tool over JSON-RPC.
- Changelog entries are fragments in =changelog.d=, and =towncrier build= collects them into =CHANGELOG.md=.
- Comments now give the reasons for the default lease, the idle poll of the pane, and the ready bench window.
- Release archives and crates.io publishes are built with Rust 1.97.1, the toolchain the check jobs use.
  =cargo deny check= no longer warns about a license allowance that matches no crate.
- The version is written by hand only in the workspace =Cargo.toml=.
  cog writes the other copies, and CI fails when they drift.
- Tokio is 1.53.3, which closes RUSTSEC-2026-0386.
- claimdag-mcp builds on rmcp 3.9.0, which covers RUSTSEC-2026-0457, RUSTSEC-2026-0461 and RUSTSEC-2026-0462, so =cargo deny check= passes.
  The server returns =ServerConfig=, the name rmcp 3.9.0 uses in place of the deprecated =ServerInfo= alias.

* 0.8.0 (2026-10-20)

- claimdag builds on capnp 0.27. capnp 0.20 marks two safe functions
  unsound (RUSTSEC-2025-0143), and the code generated from the schema
  calls one of them, so =cargo deny check= failed in every crate that
  depends on claimdag. The schema is unchanged and so are its type ids
  and struct layouts. A =work.bin= that 0.7.1 wrote opens, and saving the
  graph again writes the same bytes. A test reads such a file.
- Each release archive gets a GitHub build attestation from the release workflow, so =gh attestation verify= and the ljos installer can check that this repository built it. Releases before this one have none, and the installer counts them as not published.
- The docs no longer say the ledger keeps a reopened node's completion.
  The ledger is in memory only and =work.bin= does not store it, so each
  command-line call starts with it empty. =reopen= keeps no record of the
  earlier completion on disk.
- =release= and =complete= need an actor. =--actor= defaulted to the zero
  id, and the graph read zero as "anyone", so a call that named nobody
  could hand back or finish another seat's claim. A call with no =--actor=,
  or with the zero id, is refused. =--force= acts for nobody: it prints a
  line on stderr and appends one to =forced.log= in the graph directory.
  The library has =release_forced= and =complete_forced= for the same.
- =complete --status done= is refused while a dependency is unfinished,
  and the refusal names each open dependency with its status. A node could
  be marked done with its dependency still ready, and its dependents were
  then promoted. =failed= and =cancelled= still go through.
- A writer refuses a =work.bin= it cannot read. The command line, the MCP
  server and the pane loaded such a snapshot as an empty graph, and the
  next save kept only the node being written: on a truncated snapshot one
  =upsert= dropped 75 nodes to 1. The refusal names the file and says to
  restore it or move it aside. The snapshot is synced before the rename
  and the directory after it.
- The pane takes the graph lock for a claim, a completion or a reclaim, as
  the command line and the MCP server do. It loaded and saved without it,
  so a claim made elsewhere in between was overwritten.
- With no runtime directory the graph goes to =$XDG_STATE_HOME/claimdag=, else
  =~/.local/state/claimdag=, else =/tmp/claimdag-UID=. The shared
  =/tmp/claimdag= made a second user's first claim fail with =File exists=.
  A =/tmp/claimdag= this user owns that has a graph is still read while
  the new path has none. claimdag makes a default directory with mode
  0700 and refuses one another user owns, by name. A directory named by
  =CLAIMDAG_DIR= or =--dir= is used as given, whoever owns it.

* 0.7.1 (2026-10-10)

- The pane missed a second write in the same clock tick; it now compares
  a hash of the files it reads.
- The how-to says how several workers take work at once, and its list of
  tools names =claimdag_ready_balanced= and =claimdag_claim_next=.

* 0.7.0 (2026-10-09)

- =ready --balanced= and =claim-next= order ready work by role affinity
  and claim the chosen node in one step.
- The explanation names the generation a fencing token when the holder
  passes it back. Omitting =--gen= skips the check, so a reclaimed node
  can still be finished.

* 0.6.2 (2026-09-20)

- The how-to names the tools the server serves; =claimdag_complete= is
  titled as what it does; the architecture page names the ratatui pane.

* 0.6.0 (2026-09-12)

- =reopen ID [--actor ID]= and =claimdag_reopen=: a terminal node comes
  back to ready with the generation moved, so a tracker id that maps to
  one node can be sat on again. The ledger keeps the earlier completion.

* 0.5.0 (2026-09-12)

- =release ID [--actor ID]= and the MCP =claimdag_release=: hand one claim
  back before the work is terminal. Ready again, assignee cleared,
  generation moved. A holder that stops without it stays busy until the
  lease runs out.

* 0.4.0 (2026-09-12)

What a user gets:

- One mutator across processes: every command line and server call that
  changes the graph takes an advisory lock on the graph directory from load
  to save, so two workers claiming at once cannot lose each other's change.
- Leases: =reclaim --lease SECS= hands back every claim quiet for longer, and
  the generation moves so a stale holder is fenced at =complete --gen=.
- Critical path: the MCP =claimdag_ready= orders ready nodes by the work
  waiting below them, under a millisecond at four thousand nodes.
- =list --json=, =archive=, =unarchive=; the pane hands back stale claims
  with one key.
- A documentation site at https://leidarljos.github.io/claimdag/.
